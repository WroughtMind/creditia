这个项目里，哪些代码是哪个 AI 写的

creditia 读你电脑上的 git 历史，和 Claude Code、Codex、Cursor 这些工具留下的日志，一行一行对上，算出每个工具、每个模型写了多少。结果可以做成署名榜、片尾字幕、徽章和统计图，导出成图片、PDF、动图或者网页。

$ npx creditia analyze
macOS App
作品

同一份数据，很多种样子

署名榜、片尾字幕、小票、统计图，每一种都有十六种风格可选。下面这些都是同一个示例项目。

怎么算的

每一行都有出处，出处分四种

01

日志里对得上

工具把这一行写进文件时留下了记录。最可靠的一种。

02

提交里写明了

提交邮箱、Co-authored-by，或者 creditia 给提交盖的章。

03

推断

同一个提交里其余的行跟着有证据的工具走；工具自己建的分支算那个工具。单独标出来，可以关掉。

04

确定不了

记为「未确认」，不算到任何人头上。

都在你的电脑上算，不上传代码，也不调用任何模型。人的工作没法按行数算，所以单独写几个数字：发给 AI 多少条消息、review 多少次、人写了多少行；名字默认不出现。

完整的规则和已知的局限 →

日志读得到的工具能对到每一行；Copilot、Devin、Jules、Aider 这类从提交信息里识别。模型名会统一（同一个模型经过 Bedrock、OpenRouter 或者中转站，写法不一样），看得出来的话也会记下是经哪个渠道调用的。

用法

三条命令

也可以让你的 agent 来做：creditia 带了一份 skill，它会一步步来，公开任何内容之前先问你。

01

分析

在仓库里运行。第一次会下载对应平台的分析程序。

$ npx creditia analyze
02

出图

挑作品、风格和格式。--list 看全部选项。

$ npx creditia export \
    --piece roll --style cinema \
    --format png --out roll.png
03

放到 GitHub 上

把结果提交进仓库，GitHub Action 会在每次推送后更新徽章和署名页。

$ npx creditia publish
# .github/workflows/credits.yml
- uses: WroughtMind/creditia@main
  with: { site: _site, style: ink }
