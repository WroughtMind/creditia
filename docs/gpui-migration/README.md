# Creditia → GPUI Kit 迁移验收

本目录以主线 `ac82a574b0747bc5651571a3f169f4a893442f88` 为迁移范围基线。登记是源码盘点，不代表 GPUI 已实现或视觉已通过。源码位置与 `candidateSourceFingerprints` 对应本分支捕获时的文件，可能包含迁移中的重构，不声称其内容与基线提交相同。正式主线切换以本页的发布门槛为准。

- `features.json`：页面、操作、异常状态与新增要求；`anchor` 在基线源码中定位。
- `inventory.json`：从基线源码提取的风格、作品、版式、快捷键、原生命令、尺寸和持久化键。
- `CATALOG.md`：可读目录和边界说明。
- [`CANDIDATE.md`](CANDIDATE.md)：37 组功能的候选实现入口与取得验收结论所需的行为证据。源码导航和候选运行结果分别记录。
- `matrix.tsv`：逐风格 × 作品 × 版式的验收台账。默认验收状态均为 `pending`。
- `capture.mjs`：无第三方依赖的提取与漂移检查。源码目录变更后先审查差异，再更新清单。
- [`packaging/gpui-acceptance/`](../../packaging/gpui-acceptance/README.md)：独立基线与候选的全组合渲染对比、原生截图证据校验、整组进程资源采样和验收报告。机器对比、原生交互和视觉审阅分别记录。

在仓库根目录执行 `node docs/gpui-migration/capture.mjs --check` 检查目录语义和源码锚点；它允许实现函数体变化和行号移动，不把这类重构误判为目录增减。执行 `node docs/gpui-migration/capture.mjs --write` 明确更新目录快照、链接和候选源码指纹，并保留未变组合的人工验收栏。更新不会自动证明任何 GPUI 验收项通过，验收证据应另存于 `evidence/` 并在台账中关联。

## 状态规则

- `source_recorded`：已在固定基线找到实现及位置。
- `target_requirement`：本次迁移要求，当前桌面未提供完整对应功能。
- `pending`：未提供 GPUI 验收证据。
- `implemented`：代码已接入，仍需提供测试或视觉证据。
- `verified`：附对应输入、构建版本、运行平台和可复现证据。
- `not_applicable`：只能用于基线本来不支持的组合；必须说明原因，不能遮蔽待开发项。

源码指纹用于发现目录漏项及行为变更，不是像素一致或功能正确性的证明。台账必须保持桌面可见作品与共享渲染器额外作品的区别，不能只验收默认展墙。

## 固定样例与视觉证据

现有样例和测试入口会列在 `inventory.json`，其 SHA-256 用于固定输入。仅使用仓库已包含的样例；不把私人日志或绝对本机路径加入基线。

按需做全目录回归时，在基线和 GPUI 两个独立构建中使用同一份档案，并固定以下条件：

1. `zh/en`、工具/模型分组、显示/隐藏贡献者姓名、应用明暗主题。
2. 26 个桌面风格及各自有效作品/版式；共享渲染器未显示在桌面的作品另列，不能丢失 CLI/网页输出。
3. 原尺寸与 5 个公共导出尺寸；桌面目前隐藏 A4，目标应决定入口而保留共享能力。
4. 1×/2×/不同系统 DPI；中文长名、无模型、无会话、无版本标签、空归因、多个项目、很多文件和长字幕。
5. 确定的动画时间点，以及中断、恢复、重播、减少动态效果后的最终状态。

每份证据记录 `baseline_sha`、`candidate_sha`、输入哈希、字体文件哈希、平台/架构/系统、像素密度、窗口或导出尺寸、风格/作品/版式、分组及语言。保存基线、候选、差异图和具名审阅结论。全量完成状态由对应候选提交的验收报告判定；目录中明确样本范围的审阅记录不代表未列项目已通过。

输出比较分为：档案和统计值完全一致；SVG/HTML 结构及命中区域语义一致；PNG/PDF/GIF 像素或逐帧比较；字体、纹理及配色由实际审阅者具名核对（开发者或代理均须注明身份与证据）。字体转路径与字体嵌入不能当作同一种输出能力。共享模块的同一动作定义需要进入桌面预览和动画导出两条路径。

`render-matrix.mjs` 要求两个独立、固定且无已跟踪修改的 Git 检出；不把候选分支内两个入口相互比较当作主线基线。全量模式逐项覆盖 1,738 行，并保留 1,482 行桌面范围标记。默认轮换中英文、工具／模型分组和姓名开关；完整偏好交叉覆盖可用 `--preferences all`。空输出不能充当该组合已经验收的证据。

每份生成报告均记录 commit、输入及字体 SHA-256、平台、选项与输出校验和；失败时保存差异图和原始 SVG。报告不会自动给 `matrix.tsv` 的原生交互或视觉列打勾。原生截图必须由生产视图生成，性能采样必须包含真正执行的操作记录；缺失测量保持未知。

## 发布门槛

- 日常测试覆盖核心服务、共享渲染器、代表性原生交互、动画与实际导出。
- 在一个主平台使用旧项目走完分析、取消和重试、浏览、播放、修改设置、导出恢复及重启。看图选密集中文、长画幅、归因、动画及高 DPI 样例。
- macOS ARM/Intel、Windows x64、Linux x64 分别验证安装、启动、作品、导出和重启，核对平台对话框、剪贴板和卸载行为。发布只使用这些运行中实际验证的安装包。
- 同机比较启动、滚动、漫游、隐藏后 CPU，结合流式动画记录和连续使用的内存变化审阅明显退化。完整冷/热性能矩阵按需触发。
- 1,738 项继续作为功能目录和可选回归。完整共享渲染、网页及原生画面矩阵可通过工作流手动触发。具体证据格式见 [候选版发布说明](../../packaging/gpui/RELEASE.md)。
