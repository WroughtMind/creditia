# Creditia → GPUI Kit 迁移验收

本目录以主线 `ac82a574b0747bc5651571a3f169f4a893442f88` 为迁移范围基线。登记是源码盘点，不代表 GPUI 已实现或视觉已通过。源码位置与 `candidateSourceFingerprints` 对应本分支捕获时的文件，可能包含迁移中的重构，不声称其内容与基线提交相同。正式主线切换必须在全部验收通过以后进行。

- `features.json`：页面、操作、异常状态与新增要求；`anchor` 在基线源码中定位。
- `inventory.json`：从基线源码提取的风格、作品、版式、快捷键、原生命令、尺寸和持久化键。
- `CATALOG.md`：可读目录和边界说明。
- `matrix.tsv`：逐风格 × 作品 × 版式的验收台账。默认验收状态均为 `pending`。
- `capture.mjs`：无第三方依赖的提取与漂移检查。源码目录变更后先审查差异，再更新清单。

在仓库根目录执行 `node docs/gpui-migration/capture.mjs --check` 检查目录语义和源码锚点；它允许实现函数体变化和行号移动，不把这类重构误判为目录增减。执行 `node docs/gpui-migration/capture.mjs --write` 明确更新目录快照、链接和候选源码指纹，并保留未变组合的人工验收栏。更新不会自动证明任何 GPUI 验收项通过，验收证据应另存于 `evidence/` 并在台账中关联。

## 状态规则

- `source_recorded`：已在固定基线找到实现及位置。
- `target_requirement`：本次迁移要求，当前桌面未提供完整对应功能。
- `pending`：未提供 GPUI 验收证据。
- `implemented`：代码已接入，仍需提供测试或视觉证据。
- `verified`：附对应输入、构建版本、运行平台和可复现证据。
- `not_applicable`：只能用于基线本来不支持的组合；必须说明原因，不能遮蔽待开发项。

源码指纹用于发现目录漏项及行为变更，不是像素一致或功能正确性的证明。台账必须保持桌面可见作品与共享渲染器额外作品的区别，不能只验收默认展墙。

## 固定样例与视觉证据

现有样例和测试入口会列在 `inventory.json`，其 SHA-256 用于固定输入。仅使用仓库已包含的样例；不把私人日志或绝对本机路径加入基线。

视觉采集须在基线和 GPUI 两个独立构建中使用同一份档案，并固定以下条件：

1. `zh/en`、工具/模型分组、显示/隐藏贡献者姓名、应用明暗主题。
2. 26 个桌面风格及各自有效作品/版式；共享渲染器未显示在桌面的作品另列，不能丢失 CLI/网页输出。
3. 原尺寸与 5 个公共导出尺寸；桌面目前隐藏 A4，目标应决定入口而保留共享能力。
4. 1×/2×/不同系统 DPI；中文长名、无模型、无会话、无版本标签、空归因、多个项目、很多文件和长字幕。
5. 确定的动画时间点，以及中断、恢复、重播、减少动态效果后的最终状态。

每份证据记录 `baseline_sha`、`candidate_sha`、输入哈希、字体文件哈希、平台/架构/系统、像素密度、窗口或导出尺寸、风格/作品/版式、分组及语言。保存基线、候选、差异图和人工结论。当前目录没有声称已完成这些截图或视觉比较。

输出比较分为：档案和统计值完全一致；SVG/HTML 结构及命中区域语义一致；PNG/PDF/GIF 像素或逐帧比较；字体、纹理及配色人工核对。字体转路径与字体嵌入不能当作同一种输出能力。共享模块的同一动作定义需要进入桌面预览和动画导出两条路径。

## 发布门槛

- 功能：清单全部有结果，旧项目、证据与配置迁移及回退有测试。
- 视觉：所有有效组合有证据，中文、字体、纹理、交互和动作无未解释退化。
- 一致：同一档案跨桌面、CLI、网页及格式输出数据一致，差异有明确设计依据。
- 性能：同设备、同数据、同作品规模对照，包含所有子进程、冷/热缓存和空闲状态。
- 交付：各支持平台有可安装包、验收报告、升级回退及维护文档。缺少任一平台实机或 CI 验证时，明确列为未验证。
