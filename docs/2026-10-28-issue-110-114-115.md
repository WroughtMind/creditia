本记录区分代码回归、浏览器样例、原生 App 操作和仍待验收的入口。没有发布、替换已安装 App 或宣称全部 issue 完成。

## #110：Codex 分段历史

读取器沿 `history_base` 解析不可变 rollout ID，支持归档与 zstd、回退后的 `_rollout-id` 文件名，同时验证字节边界、排他序号和循环引用。只解析当前会话自己的执行；父会话历史与复制给子 agent 的上下文不算子会话贡献。跨分片调用与成功回执可以配对，配对保留执行当时的目录、模型和时间。

同一会话优先读取索引选中的当前文件；无索引时优先当前链的末端。缓存摘要覆盖全部依赖片段，祖先变化会重新解析。缺片、损坏或正在写入的历史给出警告，保留已存证据；完整回退可以撤销已经不在当前历史中的成功回执。源文件只读。

跨目录回归还发现并修复了 CLI 的独立问题：指定 `--repo` 时，原来仍把命令启动目录登记为项目路径，可能把同级项目纳入。现在登记显式指定的仓库路径。此修复防止新的错误登记，不自动清理旧库中已经登记的路径。

依据固定的 [Codex 源码 68b67f0](https://github.com/openai/codex/tree/68b67f0ff4f8d53d2c582e059b2c3b589f21ac93)：[HistoryPosition](https://github.com/openai/codex/blob/68b67f0ff4f8d53d2c582e059b2c3b589f21ac93/codex-rs/protocol/src/protocol.rs)、[分片序号](https://github.com/openai/codex/blob/68b67f0ff4f8d53d2c582e059b2c3b589f21ac93/codex-rs/rollout/src/ordinal.rs)、[历史链](https://github.com/openai/codex/blob/68b67f0ff4f8d53d2c582e059b2c3b589f21ac93/codex-rs/thread-store/src/local/rollout_lineage.rs)。

自动回归通过 9 个 CLI 集成测试，覆盖有/无索引、跨分片成功回执、旧缓存、祖先变更、缺片及恢复、压缩回退、父子会话、复制上下文、错误边界、循环和跨目录。测试通过真实分析程序运行，分段记录为依据官方契约构造的受控输入。本机只读检查的 302 个原生会话均为 paginated，但没有 `history_base`，因此不能宣称已完成真实分段会话端到端验收。

仍保留：真实分段样本、MCPJam 完整受管运行时/授权/账户代理、Cursor 后端、默认 zsh 入口、CodeMaker 账户和 inference.sh 独立云端入口。现有支持入口数量不变。

## #114：交互验收与修复

- 读取项目的版本信息迟到，不再覆盖之后打开的项目。
- 分析完成时保留用户后来选中的项目；手动分析其他项目仍显示该项目的成功、警告或失败，不隐藏当前项目的空状态。
- GIF 导出固定点击时的项目、语言、署名开关、分组、尺寸和版式，不受后续切换影响。
- 首次启动为空或读取失败时也安装窗口缩放处理。
- 数据源检查失败显示真实错误并允许重试，不伪装成“没有数据源”。
- 渲染失败保留旧墙并提供重试；旧墙在新墙尚未提交时不能导出或拖动。作品数据随展示一起提交，隐藏的旧墙不阻止漫游导出。
- 修复星号短瓣动画的无效 SVG 坐标：圆头半径受当前瓣长约束。常规静态标志保持原路径。
- 更新 Windows/Linux 原生验收脚本的语言设置、重新分析入口与成功提示位置。Linux 项目列表异步刷新时，脚本只在 WebDriver 明确没有执行点击的错误下重新定位；实际验收结果另列。

隔离 Chromium 使用仓库内 catnap 样例检查了 1440×900 / 900×700、设置四页、键盘放大、搜索无结果及方向键回车、行菜单、数据源 503→重试→成功、分析取消。PNG/SVG/PDF/GIF/HTML 五种格式实际生成并检查文件头。

独立 macOS 调试 App 使用临时作品库和 catnap 样例，通过画中画观察到作品墙、项目菜单、系统菜单中英文切换、⌘I 项目设置。没有覆盖 Dock 进度、Finder、路径关联与移除/加回的完整闭环。Windows/Linux 已补云端原生安装与操作验收，见下方记录；快捷键仍需专门验收。后台 WebKit 一度把页面标记为隐藏，入场动画停在第 0 帧；之后画中画正常显示，但不能用这次观察验收所有原生动画时序。

## #115：可视区域先换图

新风格先在离屏容器排好占位，优先绘制视口附近作品。可视区完成后一次替换展墙，屏幕外继续填图；尺寸未变时不重排。过期绘制结果或错误不覆盖最新选择。

Chromium、1440×900、catnap 样例的一次冷尺寸缓存测量：首次发布 108.8ms，8 张作品和 60 个占位；593.1ms 完成 68 张；整墙替换 1 次，首屏已发布作品的位置变动 0 次。另一轮缓存测量首次发布 188.4ms。900×700 连续三次切换最终停在“节目单”，68 张作品齐全。测量是本地样例观察值，不是跨设备性能保证；原生 App 的“1 秒内”仍待独立测量。
