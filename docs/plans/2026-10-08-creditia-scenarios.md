# creditia 各种情况的处理方案

状态：草案 · 2026-10-08
主方案：[`2026-10-08-creditia-plan.md`](2026-10-08-creditia-plan.md)

处理原则：

1. **不硬算。** 证据不够就降级口径，或者归入"未确认"，并告诉用户为什么。
2. **告诉用户能做什么。** 每个"数据不全"的提示后面都跟一个可以操作的建议，例如"开启证据库""安装盖章 hook""手动标注"。
3. **不丢已有成果。** 规则变化、数据源变化时，能重算的重算，不要求用户从头再来。

标注"本机已见"的，是 2026-10-08 在开发机上实际遇到的情况。

---

## 1. 数据源

| 情况 | 处理 |
|---|---|
| 日志齐全 | 正常逐行匹配，能达到"严格"口径 |
| 日志被用户清理过、换过电脑、或者从来没有日志（本机已见：魏碑 7 月没有任何 agent 日志，225 个 Codex 线程找不到内容文件） | 这一段降级到 git 信号（trailer、提交者、分支前缀）。项目页显示"证据覆盖情况"时间条，标出哪段只有 git 信号。提示用户开启证据库和盖章，保证以后不再丢 |
| 日志有保留期限（Cursor 行级记录 30 天、Claude Code 默认 30 天） | 证据库在每次分析、更新、后台采集时保存证据；首次分析时提醒用户开启后台采集 |
| 用户只用了部分工具 | 只显示检测到的工具，不出现空的类别 |
| 只有线程索引，没有内容（本机已见：Codex 有线程记录但内容文件丢失） | 用线程的分支、起始 commit、时间范围做推断，记为"标准"或"宽松"口径，不进"严格" |
| 日志格式不认识（agent 升级后改了格式） | 该数据源跳过并给出明确警告，其他数据源照常；`creditia doctor` 列出哪个工具的哪个版本不认识；用户升级 creditia 后重新分析即可 |
| agent 正在运行，数据库被占用 | 只读打开，失败时短暂重试；仍失败就跳过这个数据源并提示稍后更新 |
| 超大数据（本机已见：Cursor 对话库 2.9GB） | 只按需查询相关项目的记录，不整库复制；结果写入证据库后，下次只处理新增部分 |
| 压缩日志（本机已见：Codex `.jsonl.zst`） | 直接流式解压读取 |
| 自定义路径、便携安装 | 支持环境变量（`CODEX_HOME`、`CLAUDE_CONFIG_DIR` 等）和在设置里手动指定 |
| Windows 用户在 WSL 里跑 agent | 同时扫描 Windows 侧和各 WSL 发行版的用户目录（`\\wsl$\<发行版>\home\<用户>\`），把 Linux 路径映射回 Windows 侧的仓库 |
| 云端 agent（Cursor Cloud Agent、Codex 云端任务、Copilot coding agent 等） | 本机没有日志。用 commit 作者或邮箱（如 `cursoragent@cursor.com`）、bot 账号、PR 作者、trailer 识别，记为"标准"口径，并在明细里标"云端" |
| 不留日志的补全工具（例如部分 IDE 插件的行内补全） | 无法和人手写区分。归入"人直接编写"并在说明里写清楚"可能包含未记录的 AI 补全"；不猜测 |
| 工具已知、模型未记录（本机已见：Cursor Auto 模式记为 `default`） | 先查消息级的模型字段；查不到就显示为"Cursor Auto（模型未记录）"，不猜具体模型 |
| 同一模型在不同工具里名字不同 | 维护一份模型别名表，"按具体模型"时合并 |

## 2. 仓库

| 情况 | 处理 |
|---|---|
| squash merge、rebase、cherry-pick | 不依赖 commit hash，用 `git patch-id` 和行内容匹配 |
| force push 后历史丢失 | 只分析现存历史；作品库里旧快照保留，并标注"历史已改写" |
| agent 在 worktree 里工作（本机已见：Codex 在 `~/.codex/worktrees/…` 下工作） | 通过 git 的公共目录和远程地址把 worktree 映射回主仓库 |
| 中文或特殊字符路径（本机已见：Claude Code 把 `/Users/…/projects/魏碑` 编码成 `-Users-<user>-projects---`，不同的中文项目名会落进同一个目录） | 不靠目录名判断项目，读每条记录里的 `cwd` 字段 |
| 仓库搬过家、改过名 | 用远程地址和仓库的第一个 commit 识别是同一个仓库 |
| 一个作品有多个仓库 | 项目可以包含多个仓库，合并统计 |
| monorepo 里有多个产品 | 可以把子目录设为独立项目 |
| fork 或包含上游代码 | 只统计 fork 之后的提交；上游合并进来的代码标为"来自上游"，默认不计入 |
| 第三方代码、生成代码、lockfile、构建产物 | 默认排除规则，可在设置里调整 |
| 大规模格式化提交（例如全仓库跑一次 prettier） | 自动检测"改动行多、内容只变空白和标点"的提交，默认不计入新增，单独列出让用户确认 |
| 文件重命名、移动 | 开启 git 的重命名检测，归因跟着内容走 |
| 图片、设计稿等二进制文件 | 不按行计，按文件个数单独统计，归入"设计 / 资源"板块 |
| git 子模块 | 每个子模块作为单独的仓库，可选择是否并入项目 |
| 没有 tag | 「范围」里不显示版本选项，只提供时间段 |
| 不是 git 仓库 | 无法做代码归因。只能统计 agent 会话的投入（token、时长），并提示用户初始化 git |

## 3. 归因冲突

| 情况 | 处理 |
|---|---|
| 同一行被多个 agent 写过（A 写，B 改） | 归给最后写入、并且内容进入 commit 的那个；历程视图里能看到前面的过程 |
| agent 写完后人改了一部分 | 被人改过的行归人，记为"修正"；没改的仍归 agent |
| 人把 agent 在聊天里给出的代码手动复制进文件（没有工具调用） | 对话里的代码块也建索引，匹配上的记为"标准"口径，标注"从对话复制" |
| agent 通过脚本、代码生成器、sed 修改文件 | 编辑内容不在日志里，按"同一会话、同一时间窗口"推断，记为"标准"或"宽松" |
| 通用代码行（`}`、空 import 等）多方都能匹配上 | 过短的行不作为证据，按该 commit 的主要贡献者分配；统计冲突比例，过高时在报告里提示 |
| 多个 agent 并行（子 agent、多个 worktree） | 各自的会话分别归因；父子 agent 可以合并显示 |
| agent 审阅另一个 agent 的代码（本机已见：魏碑有 240 个 `codex-auto-review` 线程） | 记为"审阅"角色，不计入代码行，在人的参与和 Director 模板里体现 |
| agent 之间的交接文档（本机已见：魏碑 PR #193 是写给 Fable 的交接说明） | 文档按普通代码归给写它的一方，归入"方案与文档"板块 |
| 用户觉得结果不对 | 明细里点开看证据链；在校正界面手动标注，记为"手动"，其他自动结果不受影响 |

## 4. 多人协作

| 情况 | 处理 |
|---|---|
| 多人项目，只有一个人装了 creditia | 其他人的提交只能用 git 信号，证据不足的部分诚实显示为"未确认"；提示可以请队友运行 `creditia collect` 或安装盖章 hook |
| 同一个人有多个邮箱或用户名 | 支持 `.mailmap`，也可以在设置里手动合并身份 |
| 不想公开某个人的名字 | 导出时可以把人名换成别名或"团队成员" |
| 多台电脑的证据要合并 | 证据库可以导出成文件，在另一台电脑导入合并；按"路径 + 行哈希 + 时间"去重 |
| 队友用的 agent 我没有 | 他们的提交如果有 trailer 或盖章就能识别；没有的归入"未确认" |

## 5. 展示与隐私

| 情况 | 处理 |
|---|---|
| 私有仓库 | 默认只导出聚合数字；PR 标题、分支名、文件名默认隐藏 |
| PR 标题里有敏感信息 | 导出前逐条预览，可单独隐藏或改写 |
| 贡献方很多、很碎 | 小于阈值的合并成"其他"，阈值可调 |
| 某段时间证据很弱 | 图上按口径标注；导出图上印一行口径说明（可以关） |
| 用户想美化数字 | 不阻止，但口径会标在图上，且每条归因都能回查到公开仓库的 commit |
| 数据量很小（只有几个提交） | 正常展示，提示"样本较少" |

## 6. 更新与版本

| 情况 | 处理 |
|---|---|
| 日常更新 | 记录上次处理到的 commit 和每个日志的读取位置，只处理新增部分 |
| 主分支历史被改写 | 检测到后只重算受影响的部分 |
| 修改了板块规则、排除规则 | 用证据库重算，不需要重新采集 |
| creditia 升级后数据格式变了 | 作品库自动迁移；`credits.json` 带 schema 版本号，旧版本 embed 仍能读取 |
| 网站上的 embed 需要跟着更新 | 重新导出 `credits.json` 覆盖即可；阶段 2 的 GitHub Action 可以自动做 |

## 7. 跨平台

| 情况 | 处理 |
|---|---|
| Windows 路径分隔符 | Cursor 行哈希用仓库内相对路径，需要实测 Windows 下用的是 `/` 还是 `\`，两种都算一遍兼容 |
| Windows 换行符 CRLF | 规范化时去掉所有空白，CRLF 不影响行哈希；行数统计按 git 的结果 |
| Windows 长路径、中文路径 | 全程使用 Unicode 路径 API，启用长路径支持 |
| Linux 发行版 WebKitGTK 版本太旧 | 提供 AppImage 和 Flatpak，自带合适的运行环境；App 打不开时提示改用 CLI |
| 没有图形界面的服务器、CI | 只用 CLI，所有功能都能用命令完成 |
| macOS 权限 | 只读取用户目录下的文件，不需要完全磁盘访问权限；如果某个目录读不到，提示用户授权或手动指定 |
