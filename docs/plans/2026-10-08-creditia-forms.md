# creditia 展示形式清单

状态：已确认 · 2026-10-08
主方案：[`2026-10-08-creditia-plan.md`](2026-10-08-creditia-plan.md)（各形式和统计图分别排在哪个阶段，见主方案第 15 节）
原则：每种形式只回答一个问题；都读同一份档案（`credits.json`）；单个形式要像魏碑官网的 Credits 面板一样一眼能懂。

## 一、展示形式（用户已认可）

### 一眼看懂（给访客）

| 形式 | 回答的问题 | 放在哪里 |
|---|---|---|
| Tier 榜单 | 谁做的、各占多少 | 官网弹窗、关于页、App 内 |
| 署名行 | 这是谁和谁做的 | 网站页脚、App 关于页、推文末尾 |
| 徽章 | 一行概括 | README 顶部 |
| 仓库预览图 | 分享链接时带上 credits | GitHub social preview（1280×640） |

### 有情绪、适合传播

| 形式 | 回答的问题 | 放在哪里 |
|---|---|---|
| 片尾字幕 | 谁担任了什么角色 | 发布视频、关于页、App 致谢页 |
| 精力小票 | 这个作品花了多少精力 | 社交媒体 |
| 时间织带 | 项目是怎么一步步做出来的 | 官网、社交媒体 |
| 代码马赛克 | 现在这个作品由谁构成 | 官网（可悬停） |
| 个人履历卡 | 我这个人和 AI 一起做了什么（跨项目） | 个人主页、GitHub 个人 README |
| 终端名片 | `creditia fetch`，开发者炫耀用 | 终端截图 |

### 融进工作流（结构化）

| 形式 | 回答的问题 | 放在哪里 |
|---|---|---|
| `CREDITS.md` 档案 | 按版本、按 PR，谁做了什么 | 仓库根目录 |
| PR 评论 | 这个 PR 谁做的 | GitHub PR |
| Release notes 段落 | 这个版本谁做的 | 发布说明 |
| 逐行溯源 | 这一行是谁、在哪次会话写的 | `creditia blame` |
| App 内致谢页 | 应用里的 credits | 原生 App |

## 二、统计图

统计图主要给两类人看：作者自己（在 App 的"统计"页里看），以及想深究的访客（官网上放一两张）。每张都能按同一套风格导出成图片。

### 占比：谁做了多少

| 图 | 说明 | 结论 |
|---|---|---|
| 华夫饼图 | 100 个格子，每格 1%，"100 格里 87 格是 Codex"。比饼图更直观 | 首批 |
| 环形图 | 经典占比，中间放总数 | 首批 |
| 旭日图 | 内圈工具、外圈模型，一张图同时看工具和模型 | 后续 |
| 矩形树图 | 同上，用面积表达层级 | 后续 |

### 时间：怎么做出来的

| 图 | 说明 | 结论 |
|---|---|---|
| 堆叠面积图 | 每周新增代码量，按贡献方分层 | 首批 |
| 河流图 | 堆叠面积的有机形态，更好看，适合分享 | 后续 |
| 累计增长曲线 | 代码总量随时间增长，各方各一条线 | 后续 |
| 泳道图 | 每个 agent 一条泳道，会话画成一段段横条，能看到多个 agent 并行干活 | 首批 |
| 作息打卡图 | 星期 × 小时的热力格，"凌晨两点还在指挥 Codex"，偏个人、有情绪 | 首批 |
| 版本柱状图 | 每个版本一根堆叠柱 | 首批 |

### 流向与沉淀：精力去了哪里

| 图 | 说明 | 结论 |
|---|---|---|
| 沉淀漏斗 | token 消耗 → agent 写出的代码 → 提交进仓库的代码 → 至今还活着的代码。最贴合"凝聚的精力" | 首批 |
| 桑基图 | 人 → 工具 → 模型 → 板块，看工作怎么流动。信息多，适合做一张海报 | 后续 |
| 接力图（弦图） | 谁改了谁的代码、谁审了谁的代码，例如 Cursor 接手 Codex 写的界面 | 后续 |

### 人的参与

| 图 | 说明 | 结论 |
|---|---|---|
| 指挥密度曲线 | 每个 PR 平均多少条指令、几轮审阅，随时间的变化 | 后续 |
| 修正比例 | agent 写的代码里被人改过的比例 | 后续 |

### 不做

| 图 | 原因 |
|---|---|
| 雷达图（各模型在各板块的能力） | 属于模型对比，已决定往后放；雷达图本身也容易误导 |
| 箱线图、散点图、直方图 | 太偏分析，普通读者看不懂，不符合"一眼能懂" |

## 三、所需数据

| 形式 / 图 | 额外需要的数据 |
|---|---|
| 代码马赛克、沉淀漏斗的最后一级 | 存活代码（`git blame`） |
| 泳道图、作息打卡图 | 会话的起止时间（日志里有） |
| 精力小票、沉淀漏斗第一级 | token 用量（Codex 线程索引、Claude Code、Cursor 消息级字段里有） |

| 接力图、修正比例 | 行级的修改历史 |

## 四、版式与家族（2026-10-10）

同一形式在不同**版式家族**下结构不同，不只是配色和字体。七套主题绑定六个家族：

| 家族 | 结构语言 | 主题 |
|---|---|---|
| minimal | 左对齐榜单、细进度条 | Minimal / Minimal 暗 |
| film | 居中叠放、衬线体、拉字距的小标签 | Film Credits |
| terminal | 等宽、树形连接线、点线引导、注释行 | Terminal |
| glass | 悬浮卡片、半透明层 | Glass |
| editorial | 杂志分栏、大标题、栏线 | Editorial |
| mono | 等宽表格、网格线 | Mono |

形式内版式（导出时 `--variant`）：

| 形式 | 版式 |
|---|---|
| 片尾字幕 roll | classic 居中堆叠 / columns 双栏 / billing 海报演职员表 / title 标题卡 / crawl 爬行定格 |
| 精力小票 receipt | slip 清单 / thermal 热敏纸 / folio 财务单 / stub 电影票 |
| 其余形式 | 骨架随家族切换；测试断言「七种风格的 tier 互不相同」「徽章每种风格画法不同」 |

徽章也按家族各画各的：电影衬线、终端提示符、玻璃胶囊、杂志字距、等宽双块、极简一行。

人的呈现规则：人不与 agent 并排排百分比。统计图里合并为「人」一层；tier 里在「未确认」下方另起一行，列名字和占总量的百分比；「由 X 主导」署名默认关、可开。
