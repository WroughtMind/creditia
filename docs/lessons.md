# Lessons

## 2026-10-08

- **产品决策以用户为准。** 方案里涉及产品取舍（平台、形态、命名、视觉方向）时，列出选项和利弊，由用户决定。不要自己定成默认值写进方案。
- **不要默认单平台。** 用户的产品要覆盖 macOS / Windows / Linux。技术选型和数据源路径都要按三平台考虑；没在对应系统上实测的，要明确标注"待实测"。
- **不要替用户假设品牌关系。** WroughtMind 是用户的 GitHub 组织，不是品牌；creditia 不需要在视觉上靠近魏碑。做视觉方案前先问清品牌定位，不要从"同一个作者的其他产品"推出"同一个品牌家族"。
- **不要把数据缺失归因到工具行为。** 魏碑的 Codex 会话内容缺失，可能是用户自己清理的。只有在代码或文档里确认过的保留规则（例如 Cursor 代码里写死的 30 天）才能写成事实；其他情况写"可能"，并考虑到别的用户可能数据齐全。
- **展示先问"看的人要什么"，不要堆功能。** 第一版展示原型做成了带四种视图、三组开关的数据看板，被用户否定。creditia 的展示对标的是魏碑官网那种一眼看懂的 tier。设计展示时先回答"看的人在几秒内想知道什么"，只做能回答这个问题的最少元素；更细的信息放进结构化记录，不塞进可视化。
- **交互和展示要给出具体形态。** 只列"三档细度"这类名称，用户无法想象实际界面。涉及展示的方案，要配可以点着看的原型，并说明每个视图里具体显示什么。
- **在说"做不到"之前先深挖。** 一开始只看了 Cursor 的会话记录，就下结论说"Cursor 没有模型字段"。实际上 Cursor 本机有逐行的 AI 代码记录（`~/.cursor/ai-tracking/ai-code-tracking.db`）。判断某个数据源能力之前，要把它的本地存储全部查一遍：数据目录、SQLite 库、安装包里的实现。

## 2026-10-08（视觉样张）

- **视觉不能当技术检查项来做。** 阶段 0b 的样张交给 subagent 用通用要求批量出了 20 张，我只检查了"有没有溢出、中文是不是方块"，没有从审美上把关，结果被用户评价为全都很丑。视觉产出要自己逐张从设计角度审：留白、层级、对比、细节是否精致，而不只是"能渲染"。
- **先做一张做到好，再铺开。** 不要一开始就出"5 种形式 × 3 种风格"。先只做最重要的一张（tier），拿出 2–3 个差异明显的方向，自己审过、改到满意，再给用户看；方向定了再扩展到其他形式。
- **占位素材会毁掉整体观感。** 字母圆形代替 logo、标注"样例数据"的水印、内部术语（声明、推断、unattributed）印在图上，都会让成品显得廉价。给用户看之前，要么换成真素材，要么明确说明哪里是占位。

## 2026-10-09（主导者署名）

- **"由 X 主导"这类署名做成可选项，默认不显示。** 用户觉得土。人的署名只在片尾字幕里以"主导"角色出现，这一处同样可以关掉。
- **片尾字幕的设计语言是标杆**：居中排布、大量留白、小号加字距的角色标签、名字做主角、模型名用灰色等宽字。其他形式往这个方向靠。

## 2026-10-09（工程）

- **zsh 不做变量分词。** 把 `--prs out/prs.json` 放进变量再 `$a` 展开，zsh 会把它当成一个参数，程序等于没收到。结果 PR 分支信息没用上，未确认从 9.9% 变成 21.6%，差点当成算法问题去查。shell 里拼参数用数组，或者直接写全。
- **没法执行时别无限堆代码。** Bash 长时间不可用的这段时间，我把 Rust 四个 crate、CLI、embed、App 全写完了，却一行都没编译过。写到一定量就该停下来向用户说明，让用户决定是等、还是自己跑编译把报错贴回来。
- **Satori 不接受浮点误差产生的长小数。** `size * 0.32` 这类算出来的 `3.5200000000000005` 会让它报 `Invalid number`。所有数值样式统一保留两位小数。

## 2026-10-10（范围）

- **魏碑只是测试数据。** 用户明确说魏碑和 creditia 没有关系：不要为了 creditia 去改魏碑的官网、README 或任何文件，也不要把魏碑写成 creditia 的"第一个真实案例"。真实案例等用户自己定。
- **发布要等用户整体验收。** 代码和测试通过不等于可以开源；在 WroughtMind 下开源、发 npm、发 Releases 都由用户发起。

## 2026-10-10（验收重构）

- **「风格不同」要落在排版结构上。** 七套风格第一版只是换颜色换字体，被用户一句「完全拉不开距离」退回。改法是引入版式家族：左对齐榜单、居中叠放、树形连接、卡片组、杂志分栏、等宽表格，同一形式在不同家族下的骨架不同。颜色和字体只是最后一层皮，不是差异本身。
- **跨端渲染差异先怀疑依赖版本。** App 里 tier 的根容器比 CLI 输出宽 114px（正好 2×57 内边距），逐元素比对后确认是 satori 0.47.1 的 standalone 把根容器 `width` 当 content-box，而渲染器依赖 0.38.2 是 border-box。把 App 的 satori 钉到与渲染器一致的版本后逐像素一致。渲染管线在哪儿跑都要锁同一个版本。
- **同页内联多张 satori SVG 会互相顶掉。** 每张 SVG 的 clipPath / mask id 都是 `satori_` 开头，统计页九张图内联后 261 个重复 id，环形图、面积图被别张图的 clip 裁没。内联前统一换成独有前缀。
- **浏览器里跑 satori 要用 `satori/standalone`。** Node 入口在 WebView 里报 `Buffer is not defined`；standalone 要 `init(await fetch(layout.wasm))`，wasm 走 `satori/layout.wasm?url` 导入。
- **本机没有 Chrome 就用 Playwright 做视觉回归。** chrome-devtools MCP 起不来，改用 Playwright + Chromium headless shell 截图和 DOM 探针，逐页核对，再配合同一数据在 Node 侧渲染的 SVG 逐元素比对，定位差异快很多。
- **satori 不支持 dotted 边框和 conic-gradient。** 未确认的虚线纹理、环形图的环，都用内联 SVG 字符串经 base64 data URI 以 `<img>` 嵌入。
- **在 creditia 仓库提交前先盖章。** 没跑 `target/release/creditia-core stamp --harness claude-code --model claude-fable-5-1` 的提交只有 `Creditia-Harness` 行、没有 `Creditia-Model` 行：hook 只能从环境变量认出工具，模型要靠 stamp 文件。另外 hook 原来用 `contains(": ")` 判断已有 trailer 块，`fix: xxx` 这种主题行单行提交时被误判、trailer 贴在主题后面没空行；判断改为「至少两段 + 键只含 ASCII 字母数字横线」。

## 2026-10-10（第二轮验收：风格不必禁欲）

- **「现代」是对 App 的要求，不是对出图风格的要求。** 我把七套风格全做成了克制、极简、现代的同一种气质，用户说「风格你没必要一定这么禁欲这么简约现代」。出图的风格要像真实世界里的片尾字幕、戏院海报、颁奖礼、报纸、游戏通关画面那样各有各的装饰和戏剧感；克制只是其中一种口味，不是默认。
- **片尾字幕要先看真电影再画。** 五个版式都是「居中排一排」的变体，用户问「你真没看过电影吗」。做任何有真实世界原型的形式，先找原型（art of the title、海报 billing block、滚屏字幕），把结构规则抄下来再动手。
- **App 文案只留标签和动作。** 解释性句子（「颜色越深，证据越直接」「分析由 CLI 完成，App 只读结果」「用右上角的七块色板切换」）全是灌水；功能要靠界面自明，说明文字一句都不要。
- **App 的主线是「挑一张图拿走」。** 概览、统计、导出三个页签里反复出现同一批图，用户要先看、再去导出页重新找一遍，这就是「使用逻辑很傻」。应该是图库 → 点一张 → 换风格 / 版式 / 尺寸 → 复制或保存，一条线走完。

## 2026-10-10（第二轮：体裁扩充）

- **追加，不要替换。** 这轮加体裁、加版式、重做 App，用户特别交代「现有的也没必要删掉」。旧主题、旧版式、旧形式一律原样保留，新内容全部是追加；重构 App 时也是重排和删文案，不是砍功能。
- **写死「版式 → 主题」的表要跟着版式一起长。** gallery.ts 里 `HOME` 只覆盖四个旧小票版式，新增 ticket / ledger / scroll 后取到 `undefined`，`THEMES.find` 返回 undefined，直接 `Cannot read properties of undefined (reading 'dark')`。凡是「新枚举 → 某个映射」的地方，加值时必须同时补映射；或者干脆在 registry 里放 `def(t)`，让默认值只有一处。
- **satori 里 `box()` 是横排、`col()` 是竖排。** 账簿那张卡把纸张容器写成了 `box`，表头和正文并排、卡片被压扁还向右溢出。竖着堆的容器（纸张、面板、卡片）一律用 `col`。
- **装饰字符先确认字体有字形。** ✦ ✷ ❦ 在所装字体里没有，渲染成方块；改名后统一只留 ◆ ★ § ═ ▲ ■ · ▪ ─。加任何符号前先在字体里确认覆盖。
- **超宽/像素字体要按家族缩放字号。** Arcade 的像素字在 classic 版式下把名字挤出画面，加 `rollScale`（arcade 0.68）并把所有版式字号乘系数，比逐个改字号省事。
- **ImageMagick montage 必须显式给字体。** 不加 `-font /System/Library/Fonts/Helvetica.ttc` 就报 unable to read font。
- **工作目录会被重置。** 每条命令都用绝对路径；用相对路径的 python/sed 会 FileNotFoundError，或悄悄改错地方。
- **App 自查用 Playwright 抓 console。** 本机没有 Chrome，chrome-devtools MCP 起不来；Playwright 的 chromium 缓存在 `~/Library/Caches/ms-playwright`，只装 `playwright` 包（`PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1`）即可复用。截图脚本要顺便挂 `pageerror` / `console` error 监听，这轮靠它确认了「no errors」。
