# 版本与开发历程柱状图

用户口径：有版本节点按版本，没有版本节点按时间。所有风格、Wall、漫游、放大与导出使用同一份分组结果。

| 档案情况 | 展示规则 |
| --- | --- |
| 有可计入的版本标签 | 按版本节点汇总新增代码；尚未落入节点的贡献放在未发布列 |
| 没有标签，或标签全部被配置排除 | 按提交日期汇总到自然月，标题为「开发历程」，说明「每月新增代码」 |
| 旧档案只有周明细 | 保留按周的真实粒度，明确说明「每周新增代码」，不将跨月的一周强塞进某月 |
| 只有一个有贡献的版本或月份 | 正常展示一根柱子 |
| 有版本节点，但缺少版本明细 | 提示重新分析；不悄悄换成时间统计 |
| 缺少时间明细 | 提示重新分析；不从总数、项目起止日期或标签名推造数据 |
| 明细存在，但没有非人类代码贡献 | 显示暂无可展示的代码贡献；不绘制假柱子 |

## 版本识别

- 只使用分析分支历史中可达、指向提交的本地标签；未合并分支的标签不参与。
- 保留用户的 `ignoreTags` 配置。默认 `archive/**` 是备份归档，不自动算作版本。其他名称不强制符合语义化版本号，夜间构建、预发布、自定义版本名均可计入。
- 按提交的先后依赖关系分配代码，避免后来补打的旧标签被新版本吞掉。并行分支按 Git 的拓扑顺序排列，不从版本号猜测继承关系。
- 同一提交只归属一个版本节点；同一提交上的标签别名以创建时间、名称稳定选定首个归属，零贡献别名不重复画柱子。
- Git 读取失败必须报告错误，不能当成「没有版本」。重新分析时重新读标签，提交未变化也会更新分组。

## 统计与显示

- 只合并真实明细；按月与按周数据不同时相加。其他贡献者和工具、模型一起排（分母是全部新增行），按名字分，关掉署名时合成「其他贡献者」；未确认归属保留为独立部分。
- 版本节点按分析结果顺序显示，未发布贡献在最后；时间分组按日期排序。同名重复节点只统计一次，空贡献节点不绘制。
- 不截断节点数量；绘图区随节点数量扩展。屏幕和导出中的名称与当前统计粒度一致。
- `credits.json` 的 `versions`、`byVersion` 保持版本含义。按月显示不会把月份写回版本数据，也不会影响发布说明。

参考：[GitHub 将发布建立在标签上](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)，[GitLab 按时间展示提交贡献](https://docs.gitlab.com/user/analytics/contributor_analytics/)。这里采用相同的语义区分；柱子的统计量仍为 Creditia 的新增代码行。[Git 的拓扑排序](https://git-scm.com/docs/git-log#Documentation/git-log.txt---topo-order)用于保证祖先版本先于其后续版本。
